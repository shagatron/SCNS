# Indoor tracing v1 templates

`patch.schema.json` is generated from the actual strict Pydantic IndoorPatch. API PATCH/POST-preview require existing selected `layer_id`, explicit mode and stable entity IDs, plus current quoted If-Match, session, Origin and CSRF. Room/node coordinates and `polyline` use top-left **reference pixels**, never GeoJSON or geographic degrees. All scope/cost/verification actor fields are derived server-side; unknown survey facts stay NULL. One physical path is one directed edge or two reversed edges sharing all physical attributes.

`patch.example.json` is model-valid with placeholder selected-layer UUID; substitute the real exact current plan ID before use. The invented standalone node is not an automatically connected destination. [Synthetic tracing bundle](../../demo/indoor/synthetic-ground.json) uses the editor's `scns-indoor-tracing-v1` local-preview envelope: synthetic=true, exact 600×400 reference dimensions and four UUID-keyed layers. The editor binds it to the selected plan and validates through POST-preview **without writes**, then requires explicit Save; it never publishes. Only demo campuses may load this fixture. UUIDs are stable, and an existing same-floor identity is explicitly updated; cross-floor relocation is refused. Larger CSV/JSON/GeoJSON staged outdoor import templates remain separate and unchanged.

See [data/API contract](../../../docs/data/indoor-editor.md) and [data-preserving Windows update/manual walkthrough](../../../docs/operations/indoor-editor.md). Do not treat template coordinates, sources or accessibility as institutional/surveyed facts.
