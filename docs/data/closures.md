# Operational restriction contract — M4B

Closures are mutable operational records, not draft or release entities. `closure_overlays` contains a monotonically increasing campus version (absent row means0); `closures` retains incident/target/reason/UTC starts/estimated end/reopening history; append-only `closure_actions` records actor/campus/key/fingerprint/result for safe lost-response retries. Existing audit records include before/after, actor and decision evidence. Migration0016 adds empty tables only, never modifies existing geometry/accounts/releases/QRs.

Supported targets are published **outdoor_edge** (one directed edge), **outdoor_path** (all currently published directions sharing physical_path_id), **indoor_edge** (one directed indoor traversal), and **connector** (entire stairs/lift/ramp/entrance group, all paths/transitions). Node/display geometry alone is not a restriction. To close both directions of an indoor corridor, record each directed edge at successive overlay versions; each operation is atomic and the first restriction is immediately conservative. Geometry editing remains draft-only.

POST `/api/v1/admin/campuses/{id}/closures`, `/{closure}/reopen`, `/{closure}/rebind` require normal server sessions/Origin/CSRF, current campus operations or system-admin permission, and a quoted **whole-overlay** `If-Match` (including `"0"`). Editor/reviewer inventory is read-only. Stable incident UUIDs are server generated. Key is unique per actor/campus: exact retries return original receipt regardless of later version; reuse with changed operation/content conflicts. Live permissions are checked after the campus transaction lock, including retries. Missing versions428; stale version409; bad target/date/evidence422. Cross-campus incident references404 after authorization; foreign campus access403. No history-delete API. Creation/reopen/rebind, version increment, retry receipt and audit commit together.

Only `operator_verified` reopening policy is supported. Estimated end is optional and informational, must follow start and does not expire the incident. Reopening requires explicit confirmed substantive inspection/resolution evidence; no repairs/accessibility are inferred from elapsed time. Reopening one overlapping incident never clears another. Reopened incidents cannot be edited/reused; create a new incident. Canceling a future incident uses a confirmed documented reopen/cancel operation. Rebind resolves a target, keeps closure start/reason, remains closed and records operator evidence; it never reopens.

GET public `/api/v1/campuses/{id}/closures` returns release_id, closure_overlay_version, checked_at, next_change_at, unresolved_count and bounded current/scheduled public restrictions. No installer/account/reopening/reconciliation evidence is public. Missing/restricted/physically changed targets are redacted to an operator-review message without target IDs or original labels/reasons. Authenticated inventory includes retained/reopened history and at most5,000 target choices with explicit truncation. History limit2,000 per campus fails safely; archival/scaled storage is future work, not deletion of operational history.

Routing uses one REPEATABLE READ transaction for immutable release projection and operational overlay. No worker-local closure cache is used. Optional `expected_closure_overlay_version` returns stale_closures409 when changed. Every result includes overlay version, live_overlay_conservative_window policy, valid_until (30-second check interval or earlier scheduled boundary), next_closure_change_at and restriction_window_end. Server applies closed targets to a request-local copy before Dijkstra; both place and confirmed QR sources use this overlay. Existing static closed/restricted/unknown-access rules still apply. A lift outage produces no_verified_step_free_route when only stairs remain, never silent stairs substitution.

Temporal policy: use max(request departure, current UTC), conservatively exclude incidents starting before at least departure+one hour. Expand monotonically if computed ETA exceeds that window and rerun until safe. Unknown ETA excludes every unreopened scheduled incident regardless of start, rather than treating unknown time as zero. Estimated ends never cause eligibility. This may exclude a path that would be reached before its scheduled closure; that is an explicit conservative limitation. Recurring campus opening-hour evaluation, arrival-time-dependent waiting/queues and automated feeds are not provided. Past departures do not reconstruct historical closure states. Not a forecast/certification of real-world safety.

Publication and rollback preserve operational tables and reuse the campus write lock. Same physical bindings retain restrictions. Missing/restricted/changed geometry/frame/selected-plan or connector bindings become **unresolved**, increment the overlay and record actor audit in the same publication transaction. Any affected unresolved restriction fails routing closed until an operator rebinds or explicitly resolves the incident. Restoring an old map never clears unresolved state or resurrects a reopened incident. Injected audit failure rolls back both pointer and overlay changes. Draft validation/review assess immutable graph capability independently; publishing a valid map never automatically repairs a live outage.

Frontend polls15seconds and checks on focus/reconnect/manual action. Route requests wait for current metadata. Overlay/release change, scheduled boundary, route-window expiry, offline, failed check or stale metadata hides old directions/map route and retains selections. Recovery requires a fresh calculation; it does not revive an invalidated result. This is online freshness management, not M4E saved-route/PWA behavior. No new outdoor GPS source is added (M4C remains unstarted).
