# Indoor tracing v1 — Milestone 3B

The master specification sections 6–9, 18 and 19 govern this slice. 3B delivers same-floor catalog and topology editing; 3C indoor/outdoor transitions, cross-floor connector records and route computation are not implemented. Existing outdoor routes use the immutable active release throughout editing.

## Coordinates and identity

Rooms, local nodes, paths and room–door access have separate `indoor_rooms`, `indoor_nodes`, `indoor_edges`, `indoor_access` tables. Each record has `(dataset_revision_id, UUID)` identity, campus, floor, current frame and selected plan source references. Composite references prevent cross-revision/campus/floor endpoints. The server assigns scope; clients cannot supply another frame, floor or source. IDs survive cloning; an existing ID cannot move floors. A room's UUID is also its canonical `places` UUID. Its geographic `point` is NULL, never a pixel value disguised as longitude/latitude. Internal canonical codes `I-{UUID without dashes}` avoid collisions with outdoor catalog codes; public/editor room codes are uppercase and unique per floor, whose identity already fixes the building. Names may repeat. Canonical aliases/department links use existing normalized catalog tables; room editing belongs in this editor, not the outdoor place form/import. A room label is a display point, not a traversal node or inferred entrance.

Use the exact reference dimensions and adapter in [floorplans.md](floorplans.md). Local points are finite `x_px,y_px` in `[0,width_px] × [0,height_px]`, top-left origin, x right/y down. `polyline` is a **pixel array** `[[x,y],…]`, not GeoJSON. The separate indoor `CRS.Simple` map projects `[height_px-y_px,x_px]`; downsampled sanitized PNGs still occupy original reference bounds. Outdoor WGS84 and indoor maps never share instances. Metric length is the full sum of Euclidean segment lengths × current approved metres/reference-pixel. Unknown scale gives NULL distance with `distance_status="unknown"`, never 0 or inferred DPI/geographic scale.

Metric tracing requires the exact selected sanitized derivative's live independent approval and independently reviewed current uniform calibration. An approved derivative without scale allows only explicitly chosen `directions_only` saves. Unapproved/mismatched plans and revoked/inactive reviewers block tracing/review. Calibration/display approval does not verify any doorway, accessibility or physical survey fact.

## Record fields and relationships

- Room: floor-local display point, code/name/kind/description, canonical aliases and same-revision department IDs, visibility, private evidence and optional verification date. Kinds: room, laboratory, office, facility, indoor_destination.
- Node: explicit corridor/junction/door/entrance kind, label, point and provenance/visibility. `entrance` is same-floor only; it creates no outdoor transition.
- Edge: stable directed ID, physical-path UUID, explicit from/to nodes, corridor/door kind, 2–500 reference vertices, nullable width/slope/step count/surface, open state, unknown/not_step_free/verified_step_free, evidence/date/visibility. Geometry exactly meets endpoints. Door paths must meet a door-kind node. An open flag is static draft content, not a live closure/schedule.
- Access: explicit room and door-node IDs, `role=door`, priority 0–1000 (lower first), open/accessibility/evidence/date/visibility. Multiple doors per room are supported; each room/door pair is unique. The dotted display relationship is not a room-centre walking edge.

A physical path has either one directed edge or two edges with reverse endpoints/vertices and identical shared physical/access/provenance attributes. The editor updates both directions together. Split creates two physical paths with one deliberately shared junction; splitting a crossing at an existing node connects it only after an explicit decision. Snap is a coordinate aid within **2 reference pixels**, not connectivity. Moves adjust incident geometry atomically and clear affected affirmative survey/access assertions; split-generated topology is unverified. Splitting a door approach retains door kind only on legs meeting an explicit door node; other legs become corridors. Delete previews via explicit confirmation and includes dependent directions/access; omitted dependencies reject the whole patch. Required physical topology cannot be inferred from proximity, room centres or intersecting lines.

Verification dates use campus timezone, cannot be future, and require substantive evidence. NULL date/width/slope/steps/surface/access remain explicitly unknown; positive steps cannot claim verified step-free. A verified_step_free claim requires dated evidence. Server assigns the verification actor. Missing/stale (>365 days) evidence is an acknowledgement-required warning; invented fixture evidence is labelled synthetic, never field proof.

## API, transactions and validation

Private prefix `/api/v1/admin/campuses/{campus}/drafts/{revision}/floors/{floor}/indoor`:

| Operation | Behavior |
|---|---|
| GET prefix | Coherent version/status, floor/plan/frame/prerequisites, departments, four keyed record layers and computed metrics |
| POST `/preview` | Typed merged proposal and computed metrics; no writes/version/audit changes; same permissions, CSRF, plan/version/prerequisite checks |
| PATCH prefix | Atomic 1–500 explicit changes, current quoted If-Match, required exact `layer_id`, explicit measurement mode |
| GET `/validation` | Current saved version, error/warning counts, bounded actionable diagnostics with affected IDs |

All calls use existing live campus permissions and protected session. Unsafe calls require Origin/CSRF. Editor/system administrator can mutate only drafts; reviewers can inspect, operations have no draft access. Campus lock → live authorization → revision row/version lock precedes writes; global draft version covers catalog, imports, outdoor graph, floors and review, not just this floor. No partial insert/delete/audit/version change survives failure. A stale retry conflicts; stable identities and CAS cannot duplicate records accidentally. Raw local form input survives failures. Two writers are tested through separate committed sessions.

Authoritative validation includes prerequisites/reference/frame binding, bounds, exact endpoint/geometry, nonzero/simple finite polylines, duplicate codes/access, public/restricted relationships, paired attributes, source/dates, unlinked rooms/doors, weak components, directed door-to/from-corridor reachability and unknown step-free connectivity. Unmapped crossings and near-duplicate coordinates require deliberate topology decisions. Local server validation is not 3C route generation. Errors block writes/review. Warnings require independent acknowledgement in exact-content review. Limits: 2,000 records/layer/floor, 500 changed records/patch, 500 returned findings 100 per spatial pair-warning category and 1,000 detailed overlapping-path pairs; exhausted diagnostics block whole-draft completeness. No large-campus load target is claimed verified.

Database guards independently enforce revision immutability, reference floor/frame/source, coordinate bounds, planar geometry/full calibrated costs, door references, paired directions and final moved-node endpoints. Changing selected floor plan/frame or any calibration/dimensions while indoor rooms/nodes depend on it is refused. Floor/building deletion retains existing dependency safeguards. Remove dependencies explicitly in an editable draft before replacement/recalibration, then retrace against the new plan; no silent reprojection/cascade.

## Recovery and exact-content release

Local undo/redo retains up to 30 actions; same-tab sessionStorage recovery is at most 2MB/two hours and clears at logout/session invalidation. All three private editors capture a recovery generation at mount; clearing a session changes it so queued effects cannot recreate ended-session buffers. Campus/draft/floor selection restores only assigned IDs. Unapplied coordinate/polyline text is retained separately, including invalid/incomplete input. Conflicts use a per-record three-way comparison: untouched changes merge, conflicting records need explicit mine/server choices. Inspection edits pause during reconciliation so the displayed proposal cannot silently become stale. Changed plan/frame requires explicit reference comparison/retracing, with latest sanitized image shown; server still checks exact plan ID, bounds and topology after reconciliation. Storage failure is visible; keep the tab open until server save succeeds. History clears on successful save; it is not server-side undo of committed revisions.

Canonical whole-content snapshots/checksums now include the four tables, their provenance, relationships and computed metrics. Cloning restores floor/layer binding before copying local topology. Existing frozen release bytes/hashes are not rewritten by 0013. Indoor edits contribute to separation-of-duties review. Restricted rooms/nodes/paths/access and private evidence, actors, original metadata/source filenames are excluded from public immutable artifacts; public references resolve only permitted floors/endpoints/rooms. Public room search/detail includes floor/code/local point, `point=null`, `navigation_mode="indoor_catalog_only"`, `routable=false`. Outdoor map rendering skips NULL geography. Attempting an indoor route returns the existing safe unavailable category; no connector/route is invented. All public floors retain `metric_navigation=false`, including calibrated topology. Historical artifacts/PNGs persist after pointer rollback.

## Fixture and templates

[Tracing fixture](../../data/demo/indoor/synthetic-ground.json) is deliberately invented for the **600×400** [synthetic ground drawing](../../data/demo/floorplans/synthetic-ground.png): three rooms (101/102 public and R1 restricted), six nodes including three doors, five paired paths (10 directions) and three explicit door links. Width/slope/steps/surface/accessibility/date are unknown. It contains private sentinel notes to test projection; they are not institutional secrets. Upload into the editor's local preview on a demo campus only; the server validates typed records before preview and never applies/publishes automatically. Versioned API schema/example are in `data/templates/indoor-v1/`. See [Windows update and manual walkthrough](../operations/indoor-editor.md). Arbitrary room/corridor auto-extraction or staged graph/indoor imports are not added; the completed M2B1 CSV/JSON/GeoJSON outdoor import workflow is preserved.
