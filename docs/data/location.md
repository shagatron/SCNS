# Outdoor location contract — M4C initial pilot

The authoritative10.6 initial-pilot exception is implemented: find/project onto eligible published outdoor polylines using the existing geometry GiST index and metre-based geography distance, suggest a nearby public outdoor anchor landmark, require explicit physical confirmation and route from that stored node. No temporary GPS split node or unverified GPS-to-path link is fabricated. This deliberately does not claim continuous precise positioning or an inferred indoor floor. Ambiguous suggestions require choosing and confirming a labelled landmark; if none is suitable, retain manual/QR starts. Wall/fence reachability is not established by proximity: the approach is unverified, never drawn as a walking path, and excluded from route distance/ETA.

GET `/api/v1/location-policy` returns bounded configured policy. POST `/api/v1/outdoor-location-match` takes campus_id, observation, profile, expected_release_id and expected_closure_overlay_version. Observation fields: latitude[-90,90], longitude[-180,180], finite positive accuracy_m, timezone-aware observed_at. Defaults: GPS_MAX_ACCURACY_M=20, GPS_MAX_AGE_SECONDS=60, GPS_MAX_PATH_DISTANCE_M=25, GPS_MAX_LANDMARK_DISTANCE_M=40; at most10seconds future clock skew accepted. Optional settings can be provided through existing.env without overwriting it; max accuracy50m/age120s/path50m/landmark100m. Client fetches policy only following explicit action; browser one-shot high-accuracy request uses maximumAge0/timeout10000ms. No watchPosition is used.

Matching is against the current immutable public release and same-transaction live overlay, not draft graph or a cached/worker-local copy. Point must be inside published campus boundary. Existing indexed geographic bounding-box filter bounds100 nearby stored directed edges; metre projection/ranking then excludes unpublished/restricted/closed/static-ineligible/step-free-unknown/stairs as appropriate. Endpoints must be public open place-anchor nodes and have eligible directed outgoing paths; no arbitrary indoor node is accepted. All unreopened scheduled restrictions are conservatively excluded when proposing a GPS start, regardless of future start time. At most5 landmark candidates are returned, with public node/label and approximate straight-line path/landmark distances, reported accuracy and expiry; raw coordinates are not echoed.

Route source discriminator `gps` contains the observation, confirmed_node_id and confirmed:true. It requires current release/overlay versions. Server repeats age/accuracy/coverage/eligibility/matching on every calculation and rejects a landmark outside current candidates. Existing mixed Dijkstra routes from the confirmed stored outdoor node through directed outdoor edges and explicit mapped entrances to eligible outdoor/indoor destinations. No accessibility or approach cost is invented; unknown ETA/distance retain existing semantics. Existing manual place and QR sources retain their contracts. No schema migration or GPS entity.

Privacy: precise coordinates exist only in transient browser/request memory and parameterized SQL matching. No database/audit/analytics/cache/storage/sessionStorage/localStorage/URL/deep-link/clipboard persistence or raw-body/coordinate logging. Route responses expose stored published route geometry and the confirmed public landmark, not the observation; errors are generic and existing SQL failures log request ID/type only. Public mutation gcTime0 removes observer-free GPS request bodies after reset/unmount; expiry, manual selection, clear/discard, permission revocation, offline/failed checks, release/overlay/profile/distance-policy changes discard confirmation. Pending one-shot callbacks are ignored after unmount/replacement; no movement trace or continuous watches. A GPS URL omits source/observation/routed state and cannot reuse GPS on reload. Do not record real-coordinate browser/network traces for support; automated fixtures are synthetic.

All policy/match/routes responses, including errors, use no-store. Invalid fields422/invalid_input; inaccurate422/location_inaccurate; age/clock422/location_stale; coverage422/location_outside_campus; no suitable path422/location_no_suitable_path; invalid confirmed landmark422/location_needs_confirmation; mismatched release/overlay409/stale_release or stale_closures; unresolved safety targets503/closure_unresolved. Unsupported/insecure browsers, denial, unavailable position and timeout retain manual/QR fallback. Public read-only requests need no admin account; normal publication/permissions remain unchanged.

The100edge proximity cap and5candidate menu can conservatively decline dense networks; large-campus performance and GPS/wall accuracy are unverified. Geometry indexing is reused, with no migration; optional future true segment split routing and surveyed approach zones are not claimed. Actual device/Windows/GPS field evidence is separate from deterministic Chromium simulation.
