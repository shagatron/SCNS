# Public map explorer: dark navigation workspace

17 October 2026. Verified parent: `feat/muj-connectivity-review` at `a30810d5b73ffd2d757f2c05de1ed2a59f2e39aa`. Branch: `redesign/map-explorer`.

The two owner-supplied dark map references guide charcoal surfaces, off-white type, restrained mint route/selection colour, a narrow destination sidebar and original category symbols. Retail logos, photos, opening hours, ratings, prices and verification badges are not copied. Existing self-hosted Inter/system fallbacks and Leaflet remain; no new dependency, paid provider, credentials or tile service.

The scrolling introduction, overview, process, directory heading/navigation anchor and about section retain their editorial style. The actual search/filter/results now live once in the explorer rather than in a second planner. The homepage campus selector and explorer campus selector control the same App state. Browse/plan, selected place, expanded panel and existing routing fields live in the existing Planner; there is no parallel route state/API.

Desktop uses a340px sidebar and a sticky large map. Browse rows have original category icons, an explicit selection action and existing route/start actions. Selecting a row or keyboard/clickable pin highlights the same entity; the selected card shows actual name/description/building/floor/aliases/code and preserves unknown access/unmapped entrances. Route here and Set as start open/focus the existing route fields. The desktop card is aligned to the right to keep the zoom control unobstructed. The card receives focus; Escape/close restores the connected triggering control, with search as a safe fallback. Nearby pins are decluttered at campus zoom using projected pixel cells; selected pins always remain, all records remain searchable and visible names appear on selected/hovered/focused pins rather than overlapping permanently.

Mobile uses one shared control tree: compact campus/search/mode controls above the map and an ordinary expandable panel below it. Collapse/expand buttons work without dragging, fixed fullscreen overlays or wheel interception. Page scrolling remains native; only a long desktop place card may scroll within its bounded height. Restrictions, offline/route failure and confirmed GPS expiry remain outside the collapsed panel. Safe-area padding and viewport-relative map height keep ordinary document scrolling available when browser bars or keyboard reduce space. Automated resized/emulated viewports are not proof of actual phone keyboard behaviour.

## Rendering and data boundaries

Inspected `OutdoorMap`, `FloorRouteMap`, public `/map` and immutable source derivative handling before implementation. Existing map responses provide public building footprints, stored outdoor path geometry and approved source overlays/attribution; they do not expose private originals. These are sufficient for dark vector presentation. Buildings, context overlays, mapped paths, closed paths, a crisp mint route with a restrained halo and endpoint/transition marks use distinct styles. Background lines do not guarantee a permitted route. Missing footprints/truncated coverage are disclosed, never inferred from screenshots, nearby POIs or private source data. No MUJ names, coordinates, counts or route results are hardcoded in application code.

Optional existing basemap configuration is unchanged and absent by default. If configured tiles fail, published vectors and text directions remain usable. There is no blanket map/image filter; approved indoor pixels and coordinate transforms remain unchanged. Floor markers use the same category selection; indoor path/frame/floor/transition logic is retained. ResizeObserver invalidates Leaflet dimensions without refitting on every resize; campus/release/route changes and explicit Fit perform bounds selection. A failed lazy map renderer has an error boundary, leaving the planner/directions usable and offering an explicit reload (GPS must be reconfirmed).

All new styling is under `.public-app .map-workspace`. Existing homepage/admin rules and routing/service/contracts remain unchanged. Stored geometry, Dijkstra objectives, verified step-free eligibility, QR/GPS confirmation, expiry/privacy, live restrictions/freshness, stale-release invalidation and offline/no-route behavior are retained. Directions-only still minimises eligible traversals, not distance/time. Metrics and nullable ETA retain original warnings; no field/accessibility or institutional approval is inferred from OSM or the metric policy.
