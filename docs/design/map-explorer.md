# Outdoor map presentation with baseline preservation

Functional baseline: `a30810d5b73ffd2d757f2c05de1ed2a59f2e39aa`. The initial structural redesign at `6baeaad` exceeded the requested visual scope; the [preservation audit](../testing/map-preservation-audit.md) supersedes its sidebar/card/panel design. Previous results did not prove feature parity.

The scrolling homepage, overview, process, complete directory and card details/actions, original navigation/anchors, planner grid/fields/defaults/native details, messages and full-width route directions are restored. App, focusPlanner and FloorRouteMap match baseline exactly. CampusExplorer retains the baseline state/handlers/query/release/closure/QR/GPS/reload logic. No new sidebar, second campus/search control, browse/plan mode, selection card, collapsed result panel or condensed replacement directions.

Only `.public-app .outdoor-panel` is styled: charcoal map background/caption/legend, approved public vectors, mint route with restrained halo, original category SVG pins and matching mint-start legend. All original geographic places and permanent labels remain. A pin directly chooses/focuses Destination and opens native route controls, exactly like the baseline click action; Original tab order is retained: pins add no tab stops; keyboard users retain the full directory actions and map pan/zoom controls. Original28px bounds/resize refit, map sizing, zoom/Fit and optional configured tiles remain. No blanket filter or invented basemap/geometry, provider or dependency.

Approved indoor images/coordinates/markers/retry/resize remain byte-for-byte baseline. Frame-safe outdoor entrance dots use only a route's exact shared stored outdoor endpoint; no pixel/GPS floor inference or new graph connections. Text directions, nullable distances/ETA, unknown access and source qualifications are unchanged. Algorithms, APIs, schema, permissions, published releases and administrative implementation are untouched.

Two bounded exceptions are explicit: API route pending/error and shared-place lookup feedback appear beside their original planner controls with unchanged copy/requests and no scroll/focus calls; search feedback stays beside original directory controls. The existing added map-only exception boundary retains the full directory/planner/text when a lazy renderer fails. It does not replace normal API/image retry or release recovery behavior.
